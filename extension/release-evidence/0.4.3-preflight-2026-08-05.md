# Extension 0.4.3 preflight evidence

This is an automated and visual preflight, not a human Chrome Web Store
authorization or a formal accessibility-conformance claim. A maintainer must
still repeat the manual checklist and sign the release decision.

## Test record

- Extension version: 0.4.3
- Prospective worktree base: `510d7d0` plus the uncommitted 0.4.3 changes
- Date: 2026-08-05
- Reviewer: automated browser/runtime checks and screenshot inspection; human
  reviewer pending
- Browser: Chromium 142.0.7444.175
- Operating system: Linux 6.6.87.2-microsoft-standard-WSL2 x86_64
- Viewport / scale: 440 x 720 CSS pixels; device scale factor 1 (100%)
- Assistive technology: none

## Interaction and accessibility

- [x] Real unpacked Chromium keyboard traversal reached every visible control
      in logical DOM order on both popup tabs.
- [x] Keyboard focus had a computed two-pixel solid outline in light and dark
      themes; the Markdown preview also exposed visible keyboard focus.
- [x] Native labels, ARIA tab relationships, icon-button names, live-region
      attributes, and native disabled state were verified in the rendered DOM.
- [x] Progress, completion, empty-selection, clipboard-denial, and
      download-denial states used the persistent polite status region and did
      not rely only on color or motion.
- [x] Processing and terminal errors remained visible, and a stale transient
      timer could not erase a newer failure.
- [x] An 80-line preview was keyboard-focused and scrolled in the constrained
      popup without trapping focus.
- [x] The conversion-in-flight guard and disabled convert button prevented
      overlapping activation, then returned to an enabled terminal state.

## Functional modes

- [x] Full-page mode preserved navigation, article, expanded live disclosure
      content, comments, and footer in the controlled fixture.
- [x] Selection mode converted the selected range and reported whitespace-only
      selection as an error.
- [x] Article mode removed surrounding chrome while preserving the authored
      title, disclosure heading, and expanded disclosure body.
- [x] Clipboard completion and a simulated clipboard denial were visible.
- [x] Download completion and a simulated download denial were visible; the
      completed download used the sanitized Markdown filename and MIME type.
- [x] Settings persisted through `chrome.storage.sync` and reset to defaults;
      corrupt values fell back to valid defaults and simulated storage failures
      were surfaced instead of reported as successful saves.
- [x] The installed manifest had no persistent host permission, and a second
      ungranted fixture origin was denied.

## Fidelity evidence

- The shared semantic fixture passed through both the Python CLI converter and
  the unpacked extension. It covers headings, expanded disclosure content,
  relative links, images and responsive candidates, a table, and a fenced code
  block whose visual lines are separate syntax-highlighter elements.
- Chromium assertions cover figure captions exactly once, custom code-block
  precedence, image inclusion/exclusion, `srcset`-only image fallback, inline
  backtick runs, exclusion of non-content source elements, and empty-download
  isolation from an older preview.
- A live check of the Draftist article expanded four disclosure controls and
  confirmed that full-page and article extraction both retained all four
  headings and bodies. Article mode retained the visible authored title rather
  than the browser-tab suffix, and full-page references were canonicalized.
  All 23 syntax-highlighted blocks retained every structural code line in both
  the CLI and extension. After structural whitespace normalization, the live
  extension full-page Markdown was 18,392 characters over 484 lines, with no
  newline run longer than two and no whitespace-only run of multiple blank
  lines outside authored fenced content.
